# Project Demo & Presentation Guide

This guide provides a step-by-step presentation script, setup checklist, and live demonstration flow for presenting the **Multi-Tenant AI Document Management & Search Platform** to clients, stakeholders, or technical leadership.

---

## 1. Pre-Demo Preparation Checklist

Ensure all backend containerized services are up, and the frontend (run separately from [DMS-frontend](https://github.com/gaurav-chaudhari-sdms-493/DMS-frontend)) is verified, 10 minutes before starting the presentation:

- [ ] **Docker Containers Running**: `docker compose ps` shows `postgres`, `redis`, `minio`, `backend`, `worker`, and `flower` in `healthy` or `running` state.
- [ ] **Web Frontend Loaded**: With `DMS-frontend` running separately, navigate to `http://localhost:3000` and verify login screen is responsive.
- [ ] **Flower Telemetry UI Open**: Open `http://localhost:5555` in a separate browser tab to show live worker task activity.
- [ ] **Swagger API Docs Open**: Open `http://localhost:8000/api/docs` to demonstrate backend endpoints if asked technical questions.
- [ ] **Sample Test Documents Ready**: Prepare 3 sample files on desktop:
  1. `Citizen_Complaint_Main_St.pdf` (scanned or digital PDF)
  2. `Q3_Financial_Analysis.docx` (Word document)
  3. `Project_Budget_2026.xlsx` (Excel spreadsheet)

---

## 2. Executive Pitch & Key Highlights

Start the demonstration with a 60-second summary:

> *"Today we are presenting an Enterprise Multi-Tenant Document Search Engine. Unlike basic keyword search or standard document drives, our platform uses Retrieval-Augmented Generation (RAG) to instantly ingest, chunk, embed, and dynamically extract metadata from any document format—whether PDFs, Word docs, or Excel sheets. It features 4-layer hybrid search, tenant isolation via PostgreSQL Row-Level Security, pre-signed AWS S3 access, and hot-swappable AI model providers."*

## 3. Step-by-Step Live Demo Script

### Act 1: User Login & Multi-Tenant Workspace
1. **Navigate to `http://localhost:3000`**.
2. **Log in** using default admin credentials:
   - **Email**: `admin@example.com`
   - **Password**: `changeme`
3. **Highlight UI Elements**:
   - Point out the clean dark-mode dashboard, Organization Name ("Default Organization"), and Drive Stats (Total Files, Total Storage Used, Chunks Indexed).
   - Show the Folder Tree hierarchy on the left sidebar.

---

### Act 2: Document Ingestion & Background Task Telemetry
1. **Drag and drop** `Citizen_Complaint_Main_St.pdf` or `Q3_Financial_Analysis.docx` into the upload modal.
2. **Observe Instant Response**:
   - Explain that the API returns an immediate `201 Created` with a `processing` status so the client UI is never blocked.
3. **Switch to Flower Tab (`http://localhost:5555`)**:
   - Show the live Celery task execution (`app.tasks.worker.process_document_task`).
   - Point out the task ID, execution time, and successful task completion (`SUCCESS`).
4. **Refresh Dashboard**:
   - Show the document status change from `processing` to `indexed`.
   - Click the document to open the **Document Details Drawer** and highlight the **Dynamic Metadata JSON** automatically generated by the LLM (e.g., `{"document_type": "complaint", "urgency": "high", "entities": ["Main St"]}`).

---

### Act 3: Hybrid Search & 4-Layer RAG Engine
1. **Click on the Search Input** or navigate to `/search`.
2. **Enter Natural Language Query**:
   > *"Search for citizen complaints regarding pothole repairs filed on Main Street"*
3. **Analyze Results Screen**:
   - **AI Summary Card**: Highlight the concise contextual answer generated by GPT-4o / Claude Haiku confirming what was found.
   - **Citation Cards**: Point out the exact document title, snippet match, and page number (`Page 2`).
   - **S3 Download Link**: Click **Download Document** to show how a secure temporary pre-signed MinIO/S3 URL is dynamically generated.
4. **Demonstrate Layer-0 Redis Semantic Caching**:
   - Submit the exact same query again.
   - Show the response time dropping to `< 10ms` with the `cached: true` badge enabled.

---

### Act 4: In-Browser Document Preview
1. **Click on any returned document** in the search or drive listing.
2. **Observe Preview Modal**:
   - For `.docx` files: Rendered instantly in clean HTML via client-side `Mammoth.js`.
   - For `.xlsx` files: Rendered as an interactive HTML table grid via `xlsx`.
   - For `.pdf` files: Rendered in native PDF viewer.
3. **Highlight Key Feature**: Users do not need to download files to their local disk to verify search context.

---

### Act 5: Row-Level Security & Tenant Data Isolation Proof
1. **Log out** of `admin@example.com`.
2. **Register a new account** via `/sign-up`:
   - **Email**: `user@acme-corp.com`
   - **Organization**: `Acme Corp`
3. **Perform a Search**:
   - Run the query *"pothole repairs"* previously uploaded by the first tenant.
   - **Result**: `0 Results Found`.
4. **Technical Explanation**:
   - Explain PostgreSQL Row-Level Security (RLS) and how `tenant_id` filtering at the database layer prevents cross-tenant data leakage even at the vector similarity level.

---

### Act 6: Hot-Swappable AI Provider Configuration
1. **Open `backend/.env`** in editor or terminal.
2. **Show parameters**:
   ```env
   AI_LLM_PROVIDER=openai  # Can be changed to anthropic or groq
   AI_EMBED_PROVIDER=openai # Can be changed to gemini or bgem3
   ```
3. **Key Talking Point**:
   > *"The platform is completely vendor-agnostic. Organizations can switch from OpenAI to Anthropic, Groq Llama 3.3 70B, or Google Gemini by changing simple environment settings without touching code."*

## 4. Q&A Technical Cheat Sheet

| Potential Question | Recommended Answer |
|--------------------|--------------------|
| **How does vector search scale to millions of docs?** | We use PostgreSQL `pgvector` with HNSW (Hierarchical Navigable Small World) indexing, which delivers logarithmic sub-millisecond nearest neighbor search over millions of vectors. |
| **How do you handle privacy and compliance?** | Data is isolated per tenant in PostgreSQL via RLS and partitioned S3 buckets. We use zero-data-retention API contracts with AI providers. |
| **What happens if a document fails ingestion?** | Celery worker retries failed parsing tasks automatically, logs error tracebacks to PostgreSQL audit logs, and marks status as `failed` for admin review. |
| **Can we run this fully on-premise without cloud LLMs?** | Yes! `AI_LLM_PROVIDER` can be pointed to a local Groq or Ollama instance and local BGE-M3 embeddings. |
